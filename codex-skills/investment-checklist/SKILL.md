## 执行流程

### 第一步：解析输入，识别所有待分析公司

### 第一步半：AI研究偏见预警

对每家公司进行"信息丰富度"快速评级（A/B/C），并在报告中标注：

| 等级 | 判断标准 | 对Checklist的影响 |
|------|---------|-----------------|
| A级 | 上市多年、数据充裕 | 正常执行，但警惕"共识陷阱"——所有指标看起来都清晰不代表真的确定 |
| B级 | 数据有限需推算 | 每个推算指标标注置信度，"好生意"判断加权考虑数据可靠性 |
| C级 | 信息极度稀缺 | 不勉强填满六关表格，诚实标注"数据不足无法判断"，聚焦可验证的核心问题 |

**核心原则**：Checklist的目标是**排除坏选择**。对于C级公司，"数据不足"不等于"不通过"，也不等于"通过"——应诚实标注为"灰色地带，需补充一手信息"，而不是因为AI无法填满表格就判为否决。

段永平说过："看不懂"有两种——一种是生意太复杂真的看不懂，一种是你还没花时间去看。AI研究的局限是容易把"资料少"和"看不懂"混为一谈。

### 第二步：并行数据收集

使用 Task 工具为**每家公司**启动独立的后台 Agent 进行数据收集（所有公司同时并行启动），每个Agent负责收集：

1. **盈利能力**：ROE（5-10年趋势）、毛利率、净利率、自由现金流
2. **估值数据**：当前股价、市值、PE(TTM)、前瞻PE、PB、股息率
3. **增长趋势**：近3年收入/利润增速
4. **财务健康**：负债水平、资本开支需求、现金储备、净现金/净负债
5. **竞争格局**：市场份额、主要竞争对手、份额变化趋势
6. **护城河证据**：品牌/转换成本/网络效应/规模效应/技术壁垒的具体证据
7. **管理层记录**：CEO履历、关键决策、持股、资本配置记录
8. **最新动态**：近6个月重大事件（业绩、并购、监管、管理层变动等）

#### TAM 天花板验证（设定增速前，必须完成）

三情景模型不是“给什么增速就算什么估值”。在填写乐观/中性/悲观增速和目标PE之前，先验证公司可触达的**收入天花板**。这里的天花板不是未经拆解的宏观行业规模，而是公司所在产业链环节在竞争格局下能够取得的收入上限；不追求虚假的精确，但必须给出可审计的边界、单位、年份和来源。

| 步骤 | 检查项 | 必须回答 |
|------|--------|---------|
| 1 | 谁在付钱？ | 识别终端付款方，并用公开财报、预算或指引加总其可验证的支出规模 |
| 2 | 多少流到这个环节？ | 拆解产业链比例，说明总预算中流向公司所在环节的百分比 |
| 3 | 公司最多能吃多少份额？ | 结合竞争者、客户集中度、产能、渠道和技术替代，给出合理的份额上限 |
| 4 | 天花板是多少？ | 计算“环节TAM × 份额上限”，得出同口径、同币种、同年度的收入天花板绝对值 |
| 5 | 当前收入占多少？ | 用正常化的当前/基准收入 ÷ 收入天花板，标注占用率：<30%跑道长，30%-60%中等，>60%接近天花板 |
| 6 | 增速能否跑到那里？ | 计算每个情景三年后收入是否超过天花板，并说明高增速还能维持几年 |

至少采用以下两种方法交叉验证，并写出差异原因：

- **自上而下**：付款方总预算 × 流向该环节的比例 × 公司可取得份额；
- **自下而上**：逐客户、逐产品、逐区域或逐席位估算可实现收入并加总；
- **管理层信号**：用CEO/公司公开的中长期目标、产能规划或客户目标作合理性校验，不能单独替代TAM计算。

额外口径约束：

- 明确天花板是**静态**还是**动态**。动态天花板必须列出市场扩张、提价、渗透率或技术替代的依据，不能只写“行业会变大”。
- 周期股使用跨周期的正常化收入，不得把上一轮景气峰值直接当成当前天花板；若竞争格局已改变，必须重估天花板。
- 消费金融、平台型公司等必须拆开“收入增长”和“利润/EPS增长”：运营杠杆可以推动利润增长，但不能因此把收入天花板上调。
- 数字不足时填“待复核”并标注置信度，不得用未经说明的行业总规模、市场宣传口径或公司市值代替收入天花板。

用统一口径展示验证结果：

| 情景 | 年增速 | 三年后收入 | 三年后收入/天花板 | TAM验证 | 处理 |
|------|-------|-----------|------------------|---------|------|
| 乐观 | | | | 通过/警告/不通过/待复核 | |
| 中性 | | | | 通过/警告/不通过/待复核 | |
| 悲观 | | | | 通过/警告/不通过/待复核 | |

计算式为：`三年后收入 = 基准收入 × (1 + 情景年增速)^3`。金额、占用率和比较必须使用精确算术，不能心算；三情景模型仍按下方 `financial_rigor.py` 工具计算目标价。

硬规则：

1. 任一情景三年后收入**超过收入天花板**：该情景不通过，必须下调增速、缩短高增长持续期或重新论证天花板，并重新计算估值；不得保留原假设后直接引用目标价。
2. 乐观情景三年后收入**超过收入天花板的80%**：必须下调乐观PE，并明确写出“增长接近天花板，后续增速将放缓、估值倍数压缩”的逻辑。若下调后仍需突破天花板才能成立，乐观情景不通过。
3. 当前收入占天花板**超过60%**，且当前估值所隐含的增长必须在预测期内突破天花板：触发快速否决；若天花板或隐含增速无法可靠验证，至少标记为“灰色地带/待复核”，不得标记为通过。

TAM验证是第五关的估值与安全边际子检查，不增加Checklist关数；最终仍按六关计分。三情景估值表必须增加“是否通过TAM验证”或同义明确标注，并区分“原始假设”和“修订后假设”。

追加检验（**必须通过工具精确计算，禁止心算**）：
```bash
python3 tools/financial_rigor.py three-scenario \
  --price {股价} --eps {EPS} --shares {股本亿} \

```
- 三情景下的估值区间（取工具输出结果）
- 先完成上述TAM验证，再输入增速和PE；报告每个情景的TAM状态，以及乐观PE是否因接近天花板而下调
- 如果判断有误，在当前价格买入最多亏多少？

## 输出格式要求

1. 每家公司独立成章，包含：六关评分表 + 核心数据表 + TAM天花板验证表 + 标注TAM状态的三情景估值表 + 关键风险（3-5条）+ 镜子测试 + 明确结论
2. 多公司时在最后附总览对比表
3. 所有评分必须使用★符号（★1-5），不含半星
4. 数据必须标注来源时间，估计值必须注明"估计"
5. 文末附结语，呼应巴菲特名言："投资的第一条规则是不要亏损"
6. 语言风格：直接、犀利、不说废话。用巴菲特/芒格/段永平的语录穿插点评

## 关键原则

- **宁可错过，不可做错**：Checklist的目标是排除坏选择，不是找到最好的
- **诚实面对能力圈**：看不懂就说看不懂，不要勉强分析
- **安全边际是生命线**：好公司买贵了也会亏钱
- **镜子测试不可跳过**：六句话说不清楚理由或增长天花板就不买，没有例外
